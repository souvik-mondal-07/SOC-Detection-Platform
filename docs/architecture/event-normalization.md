# Event Normalization (Step 4)

Normalization turns the many ways a value can be written into one standard form, so that detection rules (a later step) are written once against a single event format. Validation then decides whether the normalized value is allowed.

The rules live in `backend/app/models/normalization.py` as small pure functions. They are attached to the schemas in `models/event.py`, so every entry point (the API today, log parsers in Step 5) applies exactly the same rules. Normalization only tidies text: it never invents a mapping, and a value that is still unsupported afterwards is rejected with a clear error.

## 1. Standard event

```json
{
  "event_id": "evt_8f92a1c4d0b37e55",
  "timestamp": "2026-10-02T10:15:23Z",
  "source": "linux_auth",
  "event_type": "authentication",
  "action": "login",
  "status": "failed",
  "username": "test_user",
  "source_ip": "192.168.1.20",
  "message": "Failed password for test_user",
  "metadata": {},
  "created_at": "2026-10-02T10:15:24Z"
}
```

## 2. Rules by field

| Field | Required | Normalization | Then validated as |
| --- | --- | --- | --- |
| `source` | yes | Trim, lowercase, spaces/hyphens to `_`, then the alias table below | One of the supported sources |
| `event_type` | yes | Same, with its alias table | One of the supported event types |
| `action` | yes | Trim, lowercase, spaces/hyphens to `_` (`Privilege Change` becomes `privilege_change`) | Lowercase snake_case, up to 64 chars. Any value that fits is allowed, so the set of actions stays open |
| `status` | no | Same, with its alias table. Missing, `null` or blank becomes `unknown` | `success`, `failed`, `blocked`, `unknown` |
| `timestamp` | no | ISO 8601 date-time converted to UTC. Missing becomes ingestion time (see section 4) | A real datetime with a timezone |
| `username` | no | Trim. Blank becomes "not provided". **Case is kept** | 1 to 64 characters |
| `source_ip` | no | Trim. Blank becomes "not provided". Written in canonical form (for example IPv6 is compressed) | A valid IPv4 or IPv6 address |
| `message` | yes | Trim only. Inner spacing and case are kept, because the message is evidence | 1 to 1000 characters. Longer messages are **rejected, not truncated** |
| `metadata` | no | None | An object. Keys may not start with `$`, contain `.`, or look like credentials (`password`, `secret`, `token`, `api_key`...). Maximum 8 levels deep and 10,000 characters as JSON |

`event_id` and `created_at` are always generated by the server. Sending them (or any other unknown field) is rejected.

## 3. Alias tables

Only these aliases exist. Everything else is left as written and then validated.

| Field | Written as | Becomes |
| --- | --- | --- |
| `source` | `windows` | `windows_event` |
| | `web` | `web_application` |
| | `app` | `application` |
| `event_type` | `auth` | `authentication` |
| | `priv` | `privilege` |
| | `net` | `network` |
| | `sys` | `system` |
| | `app` | `application` |
| `status` | `failure`, `fail` | `failed` |
| | `succeeded`, `successful` | `success` |
| | `block` | `blocked` |
| | `n/a`, `na`, `none` | `unknown` |

Examples (case never matters): `FAILED`, `Failed`, ` failed ` and `Failure` all become `failed`. `SUCCESS` becomes `success`. `Authentication`, `AUTH` and `authentication` all become `authentication`. `Linux Auth` and `LINUX-AUTH` become `linux_auth`.

**Deliberately not guessed.** `denied` is not mapped, because it could mean a failed login or a blocked connection. `ok` is not mapped. `linux` is not mapped to `linux_auth`. These are rejected with an error listing the allowed values, so the sender chooses explicitly.

## 4. Timestamps

- **Accepted:** ISO 8601 date-time strings that include a timezone: `2026-10-02T10:15:23Z`, `2026-10-02T12:15:23+02:00`, `2026-10-02T10:15:23.250Z`. A space instead of `T` is allowed.
- **Stored:** as a real datetime in UTC (MongoDB `Date`), never as a string. Offsets are converted, so `12:15:23+02:00` is stored and returned as `10:15:23Z`. MongoDB keeps millisecond precision.
- **Rejected:** malformed text, date-only values (`2026-10-02`), values **without a timezone** (`2026-10-02T10:15:23`, because the time zone is ambiguous and guessing would silently skew time windows), and numbers or digit-only strings (`1696243523`, which could be seconds or milliseconds).
- **Missing timestamp:** allowed. The event gets the server's UTC time at ingestion and `metadata.timestamp_generated` is set to `true`, so it can be told apart from a time reported by the source.
- Timestamps in the future are not rejected, since clocks drift and test data is often dated ahead.

## 5. Supported values

**Sources** (logical categories only; no real Windows or Linux collection exists yet): `linux_auth`, `windows_event`, `web_application`, `network`, `application`.

**Event types:** `authentication`, `web`, `network`, `privilege`, `system`, `application`.

**Status:** `success`, `failed`, `blocked`, `unknown`.

### Decision: status when the outcome is not meaningful

Some events have no success or failure (a system notice, an informational application message). Forcing `success` would be wrong, so the neutral value is `unknown`. A missing, `null` or blank `status` is stored as `unknown`, and `n/a` maps to it. The field is never left empty, which keeps filtering and future rules simple. The limitation is that `unknown` covers both "not applicable" and "not reported"; a separate value can be added later if rules need the difference. `blocked` means a control prevented the action (for example a firewall), which is different from `failed`.

### Extending

- **New event type or source:** add a member to the enum in `models/event.py`. Event types are intended to grow. Sources will grow with the parsers in Step 5.
- **New alias:** add one line to the matching table in `models/normalization.py` and a test.

## 6. Where web and network details go

Fields such as `http_method`, `url_path`, `http_status`, `destination_ip`, `destination_port` and `protocol` are not top-level fields in this step. Sample files keep them inside `metadata` (for example `metadata.http_status`). Promoting the ones that rules need into real fields, with indexes, is a decision for the parsing step.

## 7. Backward compatibility

The stored-event model accepts any snake_case `source`, while new events must use the supported list. This keeps events written before Step 4 readable (the Step 3 seed script used `audit_log` for one event; it now uses `linux_auth`).
